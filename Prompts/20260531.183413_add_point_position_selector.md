# User Prompt
```
how does the app determine if i am adding before the first item on route or after the last item of the route?

At any point in time when the route is being travelled, the "I am here" row is always between two points.  It is never before the first or after the last.

since "I am here" is always between two points... how do you add a new Point to the list before the first or after the last?

should there be an option in the "Add point" screen asking if the point to be added is between the currently enclosed points, or before start, or after end?

Please implement.  Also add all the above discussions to the MD file.
```

## Overview of Discussions

### 1. Placement of the "I am here" Card
- **Minimum Average Distance Algorithm**: During route tracking, the app calculates direct GPS distances to all active route points. For each sequential segment between adjacent points `Point i` and `Point i+1`, we compute the average distance to both endpoints. The segment with the minimum average distance determines the user's current segment (`minIndex` to `minIndex + 1`).
- **Binary Division**: All points from index `0` to `minIndex` are classified as **Receding** (already passed). All points from index `minIndex + 1` to `M-1` are classified as **Approaching** (yet to be reached).
- **Positioning**: The `"I am here"` custom card is injected dynamically at the boundary between receding and approaching points: `userRowPosition = receding.size()`.
- **Constraint**: During active travel, the user is always bounded between two points (never before the first or after the last). Therefore, `receding.size() >= 1` and `approaching.size() >= 1` always holds true, meaning the `"I am here"` card is safely nested within the list.

### 2. How to Add a New Point at the Current Position
- When traveling and recording a new point at your current location, it naturally belongs **between the last passed point and the next upcoming point** (i.e. in the middle of the route segment).
- To support flexibility (like planning a route beforehand or manually overriding GPS errors), it is desirable to have a **Route Position Selector** in the "Add Point" screen.

### 3. Design of the Route Position Selector
When adding a new point:
- Show a **Route Insertion Position** selector with the following options:
  - **At the End of Route (Default)**: Appends the point to the very end of the route.
  - **At the Beginning of Route**: Inserts the point as the new starting point of the route.
  - **Automatically at Current Location Segment**: (Enabled only if active GPS/traveling location is available) E.g., `"Automatically between [Point B] and [Point C]"`.
- For editing an existing point, this selector is hidden because the point already has a fixed position on the route.

## Implementation Plan

### 1. Update `PointAdapter.java`
- Add a public getter for `userRowPosition`:
  ```java
  public int getUserRowPosition() {
      return this.userRowPosition;
  }
  ```

### 2. Update `RouteDetailsActivity.java`
- When starting `AddPointActivity` from the Add Point Floating Action Button (FAB), pass the active `userRowPosition` from the adapter:
  ```java
  intent.putExtra("USER_ROW_POSITION", adapter != null ? adapter.getUserRowPosition() : -1);
  ```

### 3. Update `activity_add_point.xml`
- Insert a `TextView` header and a `RadioGroup` containing:
  - `radioPositionEnd` (checked by default)
  - `radioPositionStart`
  - `radioPositionAuto` (initially hidden, dynamically shown if traveling context exists)
- Re-constraint `buttonSave` to sit below the `RadioGroup`.

### 4. Update `AddPointActivity.java`
- Load the `Route` object inside `onCreate()` and store it as a member variable `currentRoute` for unified loading/saving.
- In `onCreate()`, extract the active (non-deleted) points:
  - If `userRowPosition` is passed and valid (i.e., `userRowPosition > 0` and `userRowPosition < activePoints.size()`):
    - Retrieve the surrounding points: `prevPoint = activePoints.get(userRowPosition - 1)` and `nextPoint = activePoints.get(userRowPosition)`.
    - Update `radioPositionAuto` text to `"Automatically between " + prevPoint.getName() + " and " + nextPoint.getName()`.
    - Make `radioPositionAuto` visible and set it as checked by default.
  - If editing an existing point (`pointId != null`), hide the position selector views.
- In `savePoint()`:
  - If in **Add Mode** (`pointId == null`):
    - If `radioPositionStart` is checked: Insert `newPoint` at index `0`.
    - If `radioPositionAuto` is checked: Locate the index of `prevPoint` in `currentRoute.getPoints()` and insert `newPoint` immediately after it.
    - If `radioPositionEnd` is checked: Append `newPoint` to the end of the list.
  - Call `FileUtils.saveRoute(this, currentRoute)` to automatically recalculate linked pointers and write to disk.
